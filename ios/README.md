# ReelHouse for iPhone and iPad

The iOS/iPadOS client of ReelHouse, a self-hosted media server: Movies & TV, Music and Podcasts.
SwiftUI, Swift 6, iOS 17+. The same target also builds for macOS 14+ (not the focus; it compiles).

- Product / display name: `ReelHouse`
- Bundle id: `com.reelhouse.client` (team `G4GK5372G8`)
- Server discovery: Bonjour `_reelhouse._tcp`
- Default server ports: HTTP `3350`, HTTPS `3453`

## Build and run

Open `ReelHouse.xcodeproj` in Xcode, pick the `ReelHouse` scheme and an iPhone or iPad, and run.
There are no package dependencies.

From the command line (no signing needed for the simulator):

```sh
xcodebuild -project ReelHouse.xcodeproj -scheme ReelHouse \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

On first launch the app looks for a ReelHouse server on the local network, or takes an address
typed in (`192.168.1.50` becomes `http://192.168.1.50:3350`). If the server's HTTPS certificate
isn't trusted by the device, the app checks the certificate against the server's own certificate
authority (`/api/certificate-authority`) and falls back to the plain-HTTP port on the local network.

## Push notifications

New podcast episodes, finished downloads and sign-in alerts arrive as notifications
(`App/PushNotificationCoordinator.swift`). The app asks for permission once someone is signed in,
registers its token with the server on every launch (`POST /api/push/devices`) and unregisters on
sign-out. Tapping one opens the episode/show (`AudioRouter`) or the movie/show (`MediaRouter`).
Settings → Notifications shows the state and has a Send Test Notification button.

To build with push for a real iPhone:

- The entitlement `aps-environment` is in `ReelHouse/ReelHouse-iOS.entitlements` (and the
  simulator file). Sign with team `G4GK5372G8`, automatic signing, and pass
  `-allowProvisioningUpdates` on the command line, so Xcode enables Push on the
  `com.reelhouse.client` App ID by itself:
  ```sh
  xcodebuild -project ReelHouse.xcodeproj -scheme ReelHouse -configuration Release \
    -destination generic/platform=iOS -allowProvisioningUpdates build
  ```
- The server needs the team's APNs key. A build installed from Xcode gets "sandbox" tokens and a
  TestFlight/App Store build gets production ones; the app reports which, so nothing to switch.
- The Simulator only receives a push you drag onto it as an `.apns` file; test on a phone.

Setup on the server, and what each notification carries: [../server/docs/PUSH.md](../server/docs/PUSH.md).

The project uses Xcode's folder-synchronised groups: any file added under `ReelHouse/` is part of
the app, with no project-file edit.

## Layout

| Folder | What is in it |
| --- | --- |
| `ReelHouse/App` | `ReelHouseApp` (entry point) and `AppModel` (connection, sign-in, which sections exist) |
| `ReelHouse/Networking` | `ReelHouseClient`, Keychain login, server identity (certificate trust), address recovery |
| `ReelHouse/Movies` | Library, detail, playback and resume, subtitles, libraries admin, network folders, Import a List, "+ Add" downloads (search, releases, queue, sites, VPN) |
| `ReelHouse/Music`, `ReelHouse/Podcasts` | The two audio sections |
| `ReelHouse/Audio` | The shared player, Now Playing, mini player, offline downloads, speakers, wake-up alarms, stats, audio settings |
| `ReelHouse/CarPlay` | CarPlay browsing for Music and Podcasts (see below) |
| `ReelHouse/Views` | Root navigation and tab bar, server setup, sign-in, Settings, accounts, server login, server settings |
| `ReelHouse/Design`, `ReelHouse/Models` | Theme and input styles; auth, settings-schema and version models |
| `scripts/make-icon.py` | Draws the placeholder app icon (needs Pillow) |
| `scripts/check-address-recovery.sh` | Checks the local/remote address recovery rules with a real URLSession and a stub server |

## CarPlay

`CarPlay/CarPlaySceneDelegate.swift` and the CarPlay scene in `Info.plist` are in place, but the
app does **not** carry the `com.apple.developer.carplay-audio` entitlement: Apple grants it per
bundle id, so it has to be requested for `com.reelhouse.client`. Once granted, add it to
`ReelHouse/ReelHouse-iOS.entitlements` and `ReelHouse/ReelHouse-iOS-Simulator.entitlements`. Until
then CarPlay never starts the scene and the code is inert.

## App icon

The icon is a placeholder (a film reel in a house on a dark background), generated by
`python3 scripts/make-icon.py`. Replace the PNGs in
`ReelHouse/Resources/Assets.xcassets/AppIcon.appiconset` when there is real artwork.

## What was dropped from the app this came from

ReelHouse began as the media part of a larger home-server app. Everything that was not media is gone:

- Cameras: live view, events feed, timeline, trigger zones, PTZ, known faces and vehicles, camera
  admin and discovery, and using the device itself as a camera (with the WebRTC package)
- The Organizer (and its package, Home Screen widgets, share extension, Quick Add, Mac widgets,
  Reminders inbox, voice capture, background refresh), including "Save to Organizer Note" on a
  podcast bookmark
- Weather, Device Hub, the security alarm, schedules, Family Files, HomeKit, licensing, backup,
  prompt profiles, host reboot, the server health and AI speed panels
- Push notifications (no APNs registration, no notification permission prompt) and the app delegate
- The CarPlay Home and Alerts tabs (Music and Podcasts remain)
- The store-build switch that hid downloads in Release builds: "+ Add", Import a List and
  Suggested for You are in every configuration
- Camera, microphone, speech and Reminders permissions; the app group; the URL scheme

Kept and adjusted:

- Root navigation is Movies, Music, Podcasts, Settings (tab bar on iPhone with the same
  customisation screen, sidebar on iPad). A section the server has switched off is hidden.
- The Morning Briefing stays; it reads the date and then plays the podcast episodes in it.
- Settings keeps the server address, audio settings, account, accounts admin, server login,
  Movies & TV libraries, the schema-driven Server Settings screen, diagnostics and acknowledgements.
